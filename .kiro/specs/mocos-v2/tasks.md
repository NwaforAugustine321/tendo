# Implementation Plan:

## Overview

This implementation plan covers all 21 requirements from the MO-COS v2 specification. Development starts with frontend (onboarding full-screen voice conversation page) and bare backend scaffolding in parallel, then proceeds through the full system build: database schema, DB Oracle tools, agent implementations, LangGraph workflow, communication layer, conversation workspace, and operation checkpoints.

## Notes

- Frontend uses the exact sigmoid.ai design system — all colors, fonts, components ported verbatim
- The onboarding page is full-screen (no sidebar) — voice-first conversation experience
- All file naming follows "no vendor prefix" convention (client.py not supabase_client.py, db/ not db_oracle/)
- Agent specs use 5-part .md files (role, backstory, goal, skill, tools) loaded at runtime
- BLA is fully asynchronous — never blocks the request-response path
- MOA uses cache-first strategy — DB Oracle only when exact data needed
- Voice recording captures blobs; actual STT/TTS wired to Google Voice Engine in Wave 6
- No E2E tests in this phase — coverage via unit, property, integration, and static analysis tests
